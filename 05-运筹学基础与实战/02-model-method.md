## 寓言：裁缝的三把尺

王城裁缝接到一件礼服订单。顾客说要好看、便宜、明天交，还不能浪费布。年轻裁缝听完就开始剪，先把最贵的丝绸铺满桌子，又临时改线条。衣服半成时，他发现布料超了、时间不够，顾客想要的腰身也没法再调。

老师傅让他停下，拿出三把尺。第一把量“想要什么”：优雅、成本、交期究竟哪个更重要；第二把量“不能越过什么”：布料、工时、尺寸限制；第三把量“能改变什么”：袖长、裙摆、用料和工序顺序。年轻裁缝这才明白，直接开剪看似快，其实把目标、约束和选择混成了一团。

故事快结束时，三把尺露出建模三要素的名字：目标函数、约束和决策变量。一个模型好不好，首先看它是否把业务问题切成这三类。

> 停一下，想一想：如果没有明确哪些量可以决策，优化模型还能告诉你“怎么改”吗？

这个故事里，礼服效果对应目标，布料工时对应约束，剪裁参数对应决策变量。建模方法的核心是先分类，再求解；没有清晰建模，后面的算法只会精确地解决一个错误问题。

## 2.1 建模三要素再深入

### 决策变量的三种类型

| 类型 | 取值 | 典型含义 | 例子 |
|------|------|---------|------|
| 连续变量 | x ≥ 0 的任何实数 | 量、金额、时间 | 运多少货、生产多少吨 |
| 整数变量 | x ∈ {0,1,2,...} | 不可分割的数量 | 用多少辆车、雇多少人 |
| 0/1 变量 | x ∈ {0,1} | 是/否决策 | 建不建厂、选不选方案 |

**经验法则**：能用连续变量的地方不要用整数。整数越多，求解越慢。

### 约束的四种常见模式

| 约束类型 | 数学形式 | 业务含义 |
|---------|---------|---------|
| 资源上限 | Σ a_i·x_i ≤ b | 不超过产能、预算、容量 |
| 需求满足 | Σ x_i ≥ d | 必须满足的需求下限 |
| 比例关系 | x_j ≤ M·y_j | 如果不建仓库，就不能从那里发货（Big-M）|
| 互斥选择 | Σ y_i ≤ 1 | 五个方案中只能选一个 |

### 目标函数的三种常见形式

| 目标形式 | 适用场景 | 注意事项 |
|---------|---------|---------|
| 最小化成本 | 运营优化 | 别忘记固定成本 vs 可变成本 |
| 最大化利润 | 商业决策 | 收入 - 成本，两者都可能是非线性 |
| 最小化最大 | 均衡负载 | min-max 形式，可以线性化 |

## 2.2 算法决策树：你的模型该用什么方法解

```
                    ┌──────────────────────┐
                    │  你写好了优化模型       │
                    └──────────┬───────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                 ▼
       ┌──────────┐     ┌──────────┐     ┌──────────────┐
       │ 线性？   │     │ 整数？   │     │ 非线性？     │
       │ 连续？   │     │          │     │              │
       └────┬─────┘     └────┬─────┘     └──────┬───────┘
            │                │                   │
            ▼                ▼                   ▼
     ┌──────────────┐ ┌──────────────┐  ┌──────────────┐
     │  LP         │ │  MIP         │  │  NLP         │
     │ 单纯形/内点 │ │ 分支定界+割  │  │ 梯度法/牛顿  │
     │ 超大规模    │ │  中大规模    │  │  小规模/特定 │
     │  秒解       │ │  分钟~小时   │  │   结构       │
     └──────────────┘ └──────────────┘  └──────────────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
             ┌──────────────┐  ┌──────────────┐
             │ 规模太大？   │  │ 能接受近似？  │
             │ 启发式       │  │ 元启发式      │
             │ 贪心/邻域搜索│  │ SA/GA/TS     │
             └──────────────┘  └──────────────┘
```

### 各类方法适用规模速查

| 方法 | 变量数上限 | 求解时间 | 最优性保证 |
|------|-----------|---------|-----------|
| LP（单纯形/内点） | 百万+ | 秒~分钟 | ✅ 全局最优 |
| MIP（分支定界） | 万~十万 | 分钟~小时 | ✅ 可证明最优 |
| 网络流专用算法 | 百万+ | 秒 | ✅ 全局最优 |
| DP | 取决于状态数 | - | ✅ 全局最优 |
| NLP（局部优化） | 万~十万 | 秒~分钟 | ❌ 可能局部最优 |
| 元启发式（SA/GA） | 任意 | 分钟~小时 | ❌ 无保证 |
| 仿真优化 | 任意 | 小时~天 | ❌ 无保证 |

## 2.3 精确算法 vs 启发式 vs 仿真：怎么选

| 精度需求 | 时效要求 | 问题规模 | 建议方案 |
|---------|---------|---------|---------|
| 必须最优 | 不限 | 中小 | 精确算法（MIP 求解器）|
| 必须最优 | 快 | 小 | 精确算法 |
| 近似即可 | 快 | 大 | 启发式（邻域搜索/贪心）|
| 近似即可 | 不限 | 超大 | 元启发式 |
| 只评估 | 不限 | 任意 | 仿真 |

**关键原则**：不要一上来就用启发式。先用 LP/MIP 求解器跑一遍——哪怕跑不完，它给的**下界（dual bound）**就是你启发式结果的「评分参考」。

## 2.4 运筹学项目的标准流程

```
业务问题
   │
   ▼
Step 1: 问题定义 ← 跟业务方对齐：决策是什么？限制是什么？目标是什么？
   │
   ▼
Step 2: 数据收集 ← 没有数据就没有模型。先确认数据可得性
   │
   ▼
Step 3: 建模 ← 五步法（画图→变量→约束→目标→量纲）
   │
   ▼
Step 4: 求解 ← 算法决策树选方法
   │
   ▼
Step 5: 验证 ← 已知解注入、极端测试、敏感性分析
   │
   ▼
Step 6: 部署 ← 集成到业务系统、自动化
   │
   ▼
Step 7: 监控 ← 实际效果 vs 模型预测、参数漂移时重训
```
